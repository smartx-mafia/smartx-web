## 1. 通用约定

### 1.1 统一响应结构

所有接口 HTTP 状态码**恒为 200**，业务状态通过 JSON 的 `code` 字段区分：

```json
{ "code": 200, "message": "SUCCESS", "data": {} }
```

| code | 含义（中文） | data 取值 | 前端处理建议 |
| --- | --- | --- | --- |
| 200 | 成功 | 业务数据或 `true` | 正常渲染 |
| 401 | 未授权：token 缺失/过期/无效/类型不符 | `false` | 回到对应流程重新获取 token（见 1.2） |
| 500 | 系统错误：代码异常、数据库错误 | `false` 或 `null` | 提示「服务异常，请稍后重试」 |
| 701 | 业务警告：参数错误、状态冲突、验证码错误等 | `false` | `message` 即可展示文案（英文原文，中文含义见第 7 节） |

### 1.2 认证方式（两级 token，双 header 通道）

两种 token 走**各自独立的请求头**，值格式统一为 `jwt <token>`（注意前缀是小写 `jwt`，不是 `Bearer`）：

| token | 请求头 | 获取时机 | 有效期 | 可访问 |
| --- | --- | --- | --- | --- |
| sessionToken | `x-session-token: jwt <token>` | `POST /waitlist_public/reserve_invite` 预留成功后返回 | 2 小时 | `/quiz/login` 注册分支（send_email_code 可选携带） |
| userToken | `Authorization: jwt <token>` | `POST /quiz/login` 成功后返回 | 15 天 | `/user/*` |

**注意**：
- 两条凭证通道完全隔离：`Authorization` 只承载 userToken，`x-session-token` 只承载 sessionToken。前端可用同一个 `jwt <token>` 拼装函数，按场景选 header 名即可；两个 header 同时存在互不干扰（各接口只读自己的通道）。
- `/quiz/*` 整组**无需预鉴权**：questions 为公开配置数据；send_email_code 防刷完全按邮箱维度；login 为注册+登录合一入口。
- `POST /quiz/login` 的**注册分支**（未注册邮箱）必须携带有效 `x-session-token`（内含邀请码，invite-only 准入）；**登录分支**（已注册邮箱）不需要任何 token。
- send_email_code / login 可选携带 sessionToken 时的作用：send_email_code 顺带延长该会话预留；login 注册分支从中取邀请码。
- `/user/*` 仅接受 `Authorization` 里的 userToken；sessionToken 放错到 `Authorization` 会返回 401，放在 `x-session-token` 则被 `/user/*` 忽略。
- token 过期或非法时统一返回：`{ "code": 401, "message": "Authorization error", "data": false }`。

### 1.3 数据格式

- **时间戳**：对外一律 Unix 毫秒（如 `joinedAt: 1787581439426`），`null` 表示无值
- **空值**：字符串空值为 `""`，对象空值为 `null`，不会出现 `undefined`
- **列表**：分页接口 `data = { list: [], total, totalPages }`；空列表为 `[]` 不是 `null`
- **分页**：`pageIndex` 从 1 开始；`pageSize` 默认 10、上限 50
- **数值**：排名、属性值等均为 Number 类型

### 1.4 防刷与请求锁

- 标注「lock 2s」的接口：同一主体（session/用户/邀请码）2 秒内只允许一次请求，被锁时返回 701 `service is busy`（服务繁忙，稍后重试），前端做好按钮防连点即可。
- 邮箱类公开接口有按邮箱的 12 小时窗口限流（详见各接口），超限返回 701 `Too many requests. Try again later.`。

## 2. 枚举与固定文案

### 2.1 邀请码视图状态（数字枚举）

`check_invite` 的 `status` 与 `my_invites` 列表项的 `status` 共用同一套数字枚举，**前端不要做字符串比较**：

| 值 | 含义 | 对应提示文案（PRD 附录 A.2 原文，直接展示） |
| --- | --- | --- |
| 0 | 可用 | （空串 `""`） |
| 1 | 被其他会话预留中（2 分钟锁/续期中） | This invite is being used in another session. Try again shortly. |
| 2 | 已被核销（一次性码已用） | This invite has already been claimed. Ask for another one. |
| 3 | 无效/不存在 | Invite code not recognized. Check the code and try again. |

> 本期邀请码**无过期语义**（无 expired 状态）。答题期间不显示倒计时，只提示：`Your invite is reserved for this session.`

### 2.2 三维判型（有序数组，按返回顺序渲染）

结果类接口的 `dimensions` 恒为 3 个元素的有序数组，**顺序即展示顺序，前端勿自行排序**：

| id | key | 中文名 | 英文名 | 两端取值（side） |
| --- | --- | --- | --- | --- |
| 0 | risk | 风险姿态 | Risk posture | `degen`（梭哈）/ `sniper`（狙击） |
| 1 | decision | 决策依据 | Decision basis | `data`（数据）/ `gut`（直觉） |
| 2 | mode | 交易模式 | Trading mode | `pack`（群体）/ `lone`（独行） |

每个元素结构：`{ id, key, nameZh, nameEn, side, sideNameZh, sideNameEn }`。

### 2.3 三项属性（有序数组，value 区间 5–99）

`attributes` 恒为 3 个元素的有序数组，每个元素：`{ id, key, nameZh, nameEn, value }`：

| id | key | 中文名 | 英文名 |
| --- | --- | --- | --- |
| 0 | conviction | 信仰 | Conviction |
| 1 | instinct | 嗅觉 | Instinct |
| 2 | resilience | 复原力 | Resilience |

### 2.4 人格 ID

| --- | --- | --- | --- |
| LQD | 送钱者 | The Liquidity Donor | 5 |

| SIG | 喊单军师 | The Signal General | 5 |
| CND | K线教主 | The Candle Prophet | 5 |

> 人格解释（description）与 roast 文案当前种子为空串，运营补录后自动生效，前端做好空串兜底。

### 2.5 结果卡片（card）结构

`inviter_card`、`/waitlist_public/result` 的 `card`、`my_result` 解锁态共用同一套卡片字段（**不含邮箱、userId、原始邀请码等任何身份信息**）：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| resultId | string | 结果 ID（可拼分享链接 `/waitlist/?result={resultId}`） |
| personaId | string | 人格 ID（见 2.4） |
| nameZh / nameEn | string | 人格中/英文名 |

| roastZh / roastEn | string | roast 文案中/英文（未补录时为 `""`） |
| colorTag | string | 结果图颜色标记（未补录时为 `""`） |
| dimensions | array | 三维判型有序数组（见 2.2） |

| bestMatch | object | 搭档：`{ personaId, nameZh, nameEn, imageUrl }` |
| naturalRival | object | 天敌：`{ personaId, nameZh, nameEn, imageUrl }` |
| configVersion | string | 结果生成时的配置版本（如 `"v1"`，历史结果按生成时配置展示） |

## 3. 前端接入流程（按用户旅程）

> 本节按用户旅程讲清每一步调哪个接口、带哪个 header、失败怎么处理。字段级完整定义见第 4–6 节，错误文案见第 7 节。

### 3.0 凭证封装与生命周期

两个 header 的规则见 1.2。推荐封装：

```js
const authValue = (token) => `jwt ${token}`;

const sessionHeaders = () => {
  const t = localStorage.getItem('sessionToken');
  return t ? { 'x-session-token': authValue(t) } : {};
};

const userHeaders = () => {
  const t = localStorage.getItem('userToken');
  return t ? { 'Authorization': authValue(t) } : {};
};
```

生命周期规则一句话：**`/quiz/login` 成功拿到 userToken 的那一刻，立即存 userToken、删 sessionToken**，两者没有重叠期。

另：六题答案由**前端本地持有**（建议 state + localStorage 双写，刷新可恢复）；后端在 `submit_quiz` 之前不保存任何中间答案，邀请码中途失效不清空本地答案，换码重新预留后继续可用。

### 3.1 落地页（无凭证）

用户从分享链接进入，URL 携带 `?invite={code}`（可能还有 `&result={resultId}`）：

```text
GET /waitlist_public/inviter_card?inviteCode=xxx
GET /waitlist_public/check_invite?inviteCode=xxx
```

- `inviter_card`：渲染「朋友的人格卡片」；`data` 为空对象 `{}` 时不展示卡片区（码不存在/官方码/邀请人未提交或已隐藏结果）。已被核销的码**仍可查卡片**，查看不占用邀请码。
- `check_invite`：`status` 数字枚举见 2.1——`0` 才放出「开始测试」按钮，非 0 展示返回的 `message` 并引导换码/稍后重试。
- 带 `&result={resultId}` 时可另调 `GET /waitlist_public/result?resultId=` 展示公开结果页（`data.hidden=true` 表示对方已隐藏）。

### 3.2 开始答题：预留邀请码 → 拿 sessionToken

用户点「开始测试」时才调用（**不要落地页就调**，会白占 120 秒锁）：

```js
// POST /waitlist_public/reserve_invite   body: { inviteCode, entryType }
const { data } = await post('/waitlist_public/reserve_invite', {
  inviteCode,
  entryType: 'referral',   // 入口来源埋点，可不传
});
localStorage.setItem('sessionToken', data.sessionToken);  // 2h 有效
// data.reservedSeconds === 120
```

失败均为 701，按 `message` 展示（被他人预留 / 已使用 / 无效）。

### 3.3 答题期间：本地作答 + 锁续期心跳

```text
GET  /quiz/questions                              （无凭证）
POST /waitlist_public/renew_reserve  body: { inviteCode }
```

- `questions` 返回 6 题（题目顺序固定、选项已乱序），题目 ID：`R1/R2`（risk）、`D1/D2`（decision）、`S1/S2`（mode）；选项 ID 形如 `R1_A`。
- 答案存本地，**不逐题上送**。
- 续期心跳：每 ~90 秒（或每答完一题）调一次 `renew_reserve`。单次续回 120s，自首次预留起累计封顶 600s。

两种续期失败分开处理：

| message | 含义 | 前端动作 |
| --- | --- | --- |
| `Invite reservation expired. Reserve again.` | 锁已掉 | 重新调 `reserve_invite`；**会拿到新 sessionToken，覆盖旧的** |
| `Invite reservation time limit reached.` | 累计 600s 到顶 | 停止心跳，提示用户尽快完成即可，**不阻断流程**（见 3.5 说明） |

### 3.4 邮箱验证码（无凭证；sessionToken 可选但建议带）

```text
GET  /waitlist_public/check_email_registered?email=     （建议）
POST /quiz/send_email_code   body: { email }            headers: sessionHeaders()
GET  /waitlist_public/check_email_code?email=           （可选）
```

- `check_email_registered`：发码前预检。`registered=true` 走「欢迎回来」登录文案，`false` 走注册文案（两种情况都继续发码，`/quiz/login` 会自动分支）。
- `send_email_code` 带上 `x-session-token` 的好处：发码成功会顺带把邀请码预留**延长到验证码有效期（300s）**，给用户填码留足时间；不带或 token 已过期则静默跳过，不报错。
- `check_email_code`：用户离开页面后返回时，判断验证码是否仍有效（`valid` + `expireSeconds` 做倒计时），避免无谓重发。

限制（701 文案直接展示）：60s 重发冷却；每邮箱 12h 最多 5 封；验证码 6 位数字、5 分钟有效；新码发出后旧码失效。

### 3.5 注册/登录合一：`/quiz/login` → 换取 userToken

```js
// POST /quiz/login   body: { email, code }
// headers: sessionHeaders()  ← 注册分支必需；纯登录（老用户回访）可不带
const { data } = await post('/quiz/login', { email, code }, sessionHeaders());

localStorage.setItem('userToken', data.token);   // 15 天
localStorage.removeItem('sessionToken');         // sessionToken 使命结束，立即丢弃

if (data.isNewUser) {
  // 注册成功 → 马上提交本地答案（3.6）
} else {
  // 老用户回访：
  //   data.resultId 非空 → 已提交过答题，直接跳结果页
  //   data.resultId 为 ""  → 已注册但未提交答题，跳答题引导
}
```

关键行为：

- **自己的锁过期不阻断注册**：只要码没被别人重新预留、也没被核销，login 注册分支依然成功。所以 600s 续期到顶后不必强制用户重来。
- 并发被抢的特例：701 `This invite has already been claimed. Ask for another one.` 时**验证码已被消耗**，换码后需引导用户重新发码。其余失败分支均不消耗验证码。
- **老用户回访路径可完全跳过 3.1–3.3**：直接 `send_email_code`（不带 session header）→ `login` → 拿 userToken 与 resultId。不需要邀请码、不消耗任何人的邀请码。

### 3.6 登录后：全部走 `Authorization`

从这里开始所有请求 headers 换成 `userHeaders()`，`x-session-token` 不再出现：

```text
POST /user/submit_quiz          body: { answers }     统一提交六题 → 算分 + 生成邀请码 → resultId
GET  /user/quiz_status                                是否已提交（submitted + resultId）
GET  /user/community_info                             Telegram/X 链接 + 完成状态
POST /user/community_complete   body: { channel }     两渠道分别点击完成（'telegram' | 'x'）
GET  /user/my_result                                  两渠道都完成后返回完整结果 + 真实排名
GET  /user/my_invites                                 我的邀请码列表（status 复用 2.1 数字枚举；可用在前、已用在后）
GET  /user/rank                                       实时排名
GET  /user/info                                       用户基础信息（登录/回访 bootstrap）
GET  /user/invite_friends                             直接邀请好友分页
```

`submit_quiz` 入参必须覆盖全部六题（详见 6.1）：

```json
{ "answers": { "R1": "R1_A", "R2": "R2_D", "D1": "D1_B", "D2": "D2_A", "S1": "S1_C", "S2": "S2_B" } }
```

重复提交幂等：不重算，直接返回已有结果。分享动作无任何奖励与解锁（仅埋点意义）；邀请码在 `submit_quiz` 后即可见。

### 3.7 401 处理（按通道区分）

| 场景 | 原因 | 前端动作 |
| --- | --- | --- |
| `/user/*` 返回 401 | userToken 过期/无效 | 清掉 userToken，引导 `send_email_code` → `login` 重新登录（不需要邀请码） |
| `/quiz/login` 注册分支返回 701 `Invite code not recognized...` | sessionToken 缺失/过期/无效 | 重新 `reserve_invite` 拿新 sessionToken 再提交（本地答案不丢） |

### 3.8 全流程时序图

```text
[落地]  inviter_card + check_invite                        （无凭证）
   ↓ 点「开始测试」
[答题]  reserve_invite → sessionToken
        renew_reserve 心跳 ×N（按 inviteCode，~90s 一次，封顶 600s）
        GET /quiz/questions → 六题本地作答
   ↓ 答完
[邮箱]  check_email_registered
        send_email_code        ← x-session-token: jwt <sessionToken>
        (check_email_code 回访补查)
   ↓ 填验证码
[准入]  POST /quiz/login       ← x-session-token: jwt <sessionToken>
        成功：存 userToken、删 sessionToken
   ↓
[用户]  submit_quiz → community_info → community_complete ×2
        → my_result / my_invites / rank / info             （全部 Authorization: jwt <userToken>）

[老用户回访] send_email_code → login → userToken + resultId  （跳过落地/答题/预留，全程不需要邀请码）

好友走主线完成注册后，邀请人排名自动提升。
```

## 4. 公开接口 /waitlist_public（无认证）

### 4.1 GET /waitlist_public/check_invite — 查询邀请码状态

- 防刷：按邀请码 lock 2s

**入参（query）**

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| inviteCode | string | 是 | 8 位小写字母数字（`/^[a-z0-9]{8}$/`，大写会被自动转小写）；格式不符返回 701 invalid 文案 |

**出参（data）**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| exists | boolean | 该码是否存在 |
| used | boolean | 是否已被核销 |
| locked | boolean | 是否正被其他会话预留 |
| status | number | 视图状态枚举 0–3（见 2.1，前端以此为准） |
| message | string | 对应提示文案（可直接展示；可用时为 `""`） |

**响应示例**

```json
可用:   { "code": 200, "message": "SUCCESS", "data": { "exists": true, "used": false, "locked": false, "status": 0, "message": "" } }
已使用: { "code": 200, "message": "SUCCESS", "data": { "exists": true, "used": true, "locked": false, "status": 2, "message": "This invite has already been claimed. Ask for another one." } }
格式错: { "code": 701, "message": "Invite code not recognized. Check the code and try again.", "data": false }
```

### 4.2 POST /waitlist_public/reserve_invite — 预留邀请码并创建答题会话

- 防刷：按邀请码 lock 2s
- 语义：预留成功即持有该码 120 秒的独占锁（防两人互抢），并签发 sessionToken

**入参（body）**

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| inviteCode | string | 是 | 8 位小写字母数字，格式不符 701 invalid 文案 |
| entryType | string | 否 | 入口来源标识（埋点用，如 `official` / `referral`），可不传 |

**出参（data）**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| sessionToken | string | 答题会话 token（后续经 `x-session-token: jwt <token>` 携带，见 1.2） |
| inviteCode | string | 回显预留的邀请码 |
| reservedSeconds | number | 本次预留秒数（120） |

**失败分支（均 701，data:false）**：按邀请码实际状态返回 2.1 节对应文案（被他人预留 / 已核销 / 无效）。

### 4.3 POST /waitlist_public/renew_reserve — 续期邀请码预留

- 防刷：按邀请码 lock 2s
- 语义：单次续期至 120s；自**首次预留**起累计封顶 600s，超过不再续期。前端可在用户答题过程中（如每答一题）调用

**入参（body）**

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| inviteCode | string | 是 | 8 位小写字母数字 |

**出参（data）**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| expireSeconds | number | 续期后的剩余秒数 |

**失败分支（701）**

| message | 中文含义 | 前端处理 |
| --- | --- | --- |
| `Invite reservation expired. Reserve again.` | 预留已失效（超时或从未预留） | 重新调 reserve_invite（本地答案不清空） |
| `Invite reservation time limit reached.` | 已达累计 600s 上限 | 引导用户尽快提交邮箱（bind 前的预留校验有乐观锁兜底） |

### 4.4 GET /waitlist_public/inviter_card — 查询邀请人卡片

- 防刷：按邀请码 lock 2s；Redis 缓存 24h（空结果短缓存 60s）
- 语义：好友从分享链接进入时，仅凭邀请码展示邀请人的公开结果卡片；**不占用邀请码**；已核销的码仍可查询

**入参（query）**

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| inviteCode | string | 是 | 8 位小写字母数字 |

**出参（data）**：卡片对象（结构见 2.5）；以下情况一律返回**空对象 `{}`**（前端按「无卡片」处理，仍可展示邀请码输入）：
- 码不存在
- 邀请人未提交答题 / 官方总号发出的码
- 邀请人已隐藏公开结果

### 4.5 GET /waitlist_public/result — 查看公开结果

- 语义：分享链接 `/waitlist/?result={resultId}` 的数据源；不占用邀请码

**入参（query）**

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| resultId | string | 是 | 非空；不存在返回 701 |

**出参（data）**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| hidden | boolean | 结果所有者是否已隐藏公开结果 |
| card | object\|null | 卡片对象（见 2.5）；`hidden=true` 时为 `null` |

**失败分支（701）**：`result not found`（结果不存在）。

### 4.6 GET /waitlist_public/check_email_code — 验证码有效性查询

- 限流：每邮箱 12 小时最多 30 次（自首次查询起算固定窗口），超限 701
- 语义：只读，**不消耗验证码、不计入错误尝试**；用于用户离开页面后返回时判断是否需要重发

**入参（query）**

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| email | string | 是 | 邮箱格式（`/^[^\s@]+@[^\s@]+\.[^\s@]+$/`），自动转小写；格式不符 701 |

**出参（data）**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| valid | boolean | 该邮箱当前是否存在有效验证码 |
| expireSeconds | number\|null | 有效时的剩余秒数（供倒计时）；无效时为 `null` |

**失败分支（701）**：`Please enter a valid email address.`（邮箱格式无效）、`Too many requests. Try again later.`（查询超限）。

### 4.7 GET /waitlist_public/check_email_registered — 邮箱注册状态查询

- 限流：每邮箱 12 小时最多 30 次，超限 701
- 语义：发验证码前预检，用于前端区分文案与流程：已注册 → 登录/回访分支；未注册 → 注册分支（需邀请码）

**入参（query）**：同 4.6 的 `email`。

**出参（data）**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| registered | boolean | 该邮箱是否已完成注册 |

### 4.8 POST /waitlist_public/issue_invite_codes — 总号批量发码（运营接口）

- 鉴权：**非 JWT**。秘钥经请求头 `x-admin-secret`（推荐）或 `body.secret` 传入，与 `.env ADMIN_ISSUE_SECRET` 恒定时间比对；错误返回 `{ code: 401, message: "Authorization error", data: false }`
- 语义：发出的码归属官方总号；数量不设上限，服务端按 1000/批分批插入；某批失败时**已发放部分照常返回**（调用方按差额重发）

**入参（body）**

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| count | number | 是 | 正整数；否则 701 `parameters missing` |
| secret | string | 否 | 秘钥（建议改走 header） |

**出参（data）**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| list | string[] | 本次实际发放的邀请码列表 |

> **该接口为运营接口，前端页面不对接**：秘钥仅存于服务端 `.env` 与运营侧脚本，严禁写入任何前端代码、配置或构建产物。

## 5. 答题接口 /quiz

### 5.1 GET /quiz/questions — 获取六道测试题

- 鉴权：**无需鉴权**（题目为公开配置数据，可在拿到邀请码前预拉取）
- 语义：题目按固定顺序返回（不打乱），**选项在服务端乱序**；不暴露判型权重与属性加点。六题在前端本地作答，统一由 `/user/submit_quiz` 提交

无入参。

**出参（data）**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| questions | array | 6 道题，按展示顺序 |
| questions[].questionId | string | 题目 ID：`R1`/`R2`/`D1`/`D2`/`S1`/`S2` |
| questions[].dimension | string | 所属判型维度：`risk`/`decision`/`mode` |
| questions[].prompt | string | 题干（英文） |
| questions[].artworkKey | string | 每题主图资源 key |
| questions[].options | array | 4 个选项（已乱序）：`{ optionId, label }` |

### 5.2 POST /quiz/send_email_code — 发送邮箱验证码

- 鉴权：**无需鉴权**（发码可发生在预留邀请码之前）；**已注册邮箱同样发码**（用于登录/回访）；可选经 `x-session-token: jwt <token>` 携带 sessionToken——有效时发送成功后顺带将该会话预留的邀请码延长至验证码有效期，无 token 或已过期则静默跳过
- 防刷：60 秒重发冷却 + 每邮箱 12 小时窗口上限 + 全局 IP 限流
- 规则：6 位数字验证码，**5 分钟有效**；60 秒重发冷却；**每邮箱 12 小时最多 5 封**（自首封起算固定窗口）；新码发出后旧码失效

**入参（body）**

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| email | string | 是 | 邮箱格式，自动转小写 |

**出参**：`data: true`

**失败分支（701）**

| message | 中文含义 |
| --- | --- |
| `Please enter a valid email address.` | 邮箱格式无效 |
| `Please wait before requesting a new code.` | 60 秒重发冷却中 |
| `Email send limit exceeded. Try again later.` | 超出每邮箱 12h/5 封发送上限 |
| `Failed to send verification code` | 邮件服务发送失败（可稍后重试，不消耗次数） |

### 5.3 POST /quiz/login — 邮箱验证码登录/注册合一入口

- 鉴权：**无需预鉴权**。按邮箱注册状态自动分支：
  - **登录分支**（已注册邮箱）：不需要任何 token；验证码通过即签发 userToken 并返回原 `resultId`——老用户回访凭此查看结果、排名与邀请数据。不需要邀请码、不核销、不发奖励（即使带着别人的邀请码来也不消耗）。
  - **注册分支**（未注册邮箱）：必须在请求头携带有效 sessionToken（`x-session-token: jwt <sessionToken>`，由 reserve_invite 签发、内含邀请码，invite-only 准入不变）。单事务完成：核销邀请码（乐观锁，并发抢码只有一人成功）→ 创建用户 → 绑定邀请关系 → 邀请人排名提升。
- **注册成功后前端应立即持 userToken 调 `/user/submit_quiz` 提交本地答案**；登录用户直接调 `/user/*` 恢复状态。

**入参（body）**

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| email | string | 是 | 邮箱格式，自动转小写 |
| code | string | 是 | 6 位数字验证码 |

**出参（data）**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| token | string | userToken（15 天有效，后续 `/user/*` 经 `Authorization: jwt <token>` 携带） |
| userId | string | 用户 ID（13 位数字） |
| isNewUser | boolean | true=本次为注册；false=本次为登录/回访 |
| resultId | string | 登录分支返回原结果 ID（未提交过答题为 `""`）；注册分支恒为 `""` |

**失败分支（701，按检查顺序）**

| message | 中文含义 | 分支 | 是否消耗验证码 |
| --- | --- | --- | --- |
| `parameters missing` | 验证码未填 | 通用 | 否 |
| `Please enter a valid email address.` | 邮箱格式无效 | 通用 | 否 |
| `user not found` | 账号被封禁 | 登录 | 否 |
| `Invite code not recognized. Check the code and try again.` | 未注册且未携带有效 sessionToken / 会话中的邀请码无效 | 注册 | 否 |
| `This invite has already been claimed. Ask for another one.` | 邀请码已被核销（含并发被抢） | 注册 | 抢码失败时验证码已消耗，需重发 |
| `This invite is being used in another session. Try again shortly.` | 预留被其他会话持有 | 注册 | 否 |
| `Verification code is incorrect or expired` | 验证码错误/过期/尝试超 5 次作废 | 通用 | 错误计数 +1 |

## 6. 用户接口 /user（userToken）

### 6.1 POST /user/submit_quiz — 统一提交六题答案

- 防刷：lock 2s

- 副作用：生成结果快照与三项属性；按人格 quota（普通 5 / 风控大师 10）一次性生成全部一次性邀请码

**入参（body）**

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| answers | object | 是 | 形如 `{"R1":"R1_A","R2":"R2_D","D1":"D1_B","D2":"D2_A","S1":"S1_C","S2":"S2_B"}`；必须覆盖全部 6 题，且每个 optionId 属于对应题目，否则 701 |

**出参（data）**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| resultId | string | 结果 ID |

**失败分支（701）**：`invalid answers`（答案不完整或选项不属于对应题目）。

### 6.2 GET /user/quiz_status — 是否已提交答题

无入参。

**出参（data）**

| 字段 | 类型 | 含义 |

| submitted | boolean | 是否已提交过答题 |

### 6.3 GET /user/my_result — 我的结果与排名

- 防刷：lock 2s
- 门控：Telegram 与 X 两项社群动作**都完成**后才返回完整结果与排名

**出参（data）— 三种形态**

{ "submitted": true, "locked": false, ...卡片字段（见 2.5）,

解锁态附加字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| rank | number | 我的真实排名（从 1 开始，排除官方总号） |
| totalUsers | number | waitlist 总人数（排除官方总号） |
| shareCompleted | number | 是否已点过分享（1/0，仅标记无奖励） |
| inviteGenerated | number | 邀请码生成完整标记（1/0） |
| joinedAt | number | 注册时间（毫秒时间戳） |

### 6.4 GET /user/community_info — 社群链接与完成状态

| links.x | string | X 关注链接 |
| telegramCompleted / xCompleted | number | 对应渠道是否完成（1/0） |

### 6.5 POST /user/community_complete — 标记社群动作完成

- 防刷：lock 2s
- 语义：当前为假验证——用户点击并打开对应渠道即算完成，重复点击幂等
- 前置：必须已提交答题，否则 701

**入参（body）**

**出参（data）**

### 6.6 GET /user/rank — 我的排名

## 7. 错误文案速查表（中英对照）

`code=701` 时 `message` 为以下英文原文，可直接展示；中文含义供前端理解与自定义文案参考：

| message（原文） | 中文含义 | 出现接口 |
| --- | --- | --- |
| `Invite code not recognized. Check the code and try again.` | 邀请码无效/格式错误/不存在；或注册分支未携带有效 sessionToken | check_invite / reserve_invite / renew_reserve / inviter_card / login |
| `This invite has already been claimed. Ask for another one.` | 邀请码已被使用（含并发被抢） | 同上 + login 注册分支核销失败 |
| `This invite is being used in another session. Try again shortly.` | 邀请码正被其他会话预留 | reserve_invite / login |
| `Invite reservation expired. Reserve again.` | 预留已失效，需重新预留 | renew_reserve |
| `Invite reservation time limit reached.` | 预留续期已达 600 秒上限 | renew_reserve |
| `result not found` | 结果 ID 不存在 | /waitlist_public/result |
| `Please enter a valid email address.` | 邮箱格式无效 | 邮箱类接口 |
| `Verification code is incorrect or expired` | 验证码错误/已过期/尝试超 5 次作废 | login |
| `Please wait before requesting a new code.` | 60 秒重发冷却中 | send_email_code |
| `Email send limit exceeded. Try again later.` | 超出每邮箱 12 小时 5 封上限 | send_email_code |
| `Failed to send verification code` | 邮件发送失败，可稍后重试 | send_email_code |
| `Too many requests. Try again later.` | 查询超出每邮箱 12 小时 30 次上限 | check_email_code / check_email_registered |
| `parameters missing` | 必填参数缺失 | 通用 |
| `invalid channel` | channel 不是 telegram/x | community_complete |
| `invalid answers` | 六题答案不完整或选项不属于对应题目 | submit_quiz |
| `Quiz not submitted yet` | 尚未提交答题（时序校验） | community_complete |
| `user not found` | 用户不存在或被封禁 | rank / login |
| `service is busy` | 2 秒请求锁生效，稍后重试 | 所有 lock 接口 |
| `authorization required` | 请求锁找不到认证主体（token 异常） | lock 中间件 |

`code=401` 时 `message` 恒为 `Authorization error`（token 缺失/过期/无效/类型不符）。
