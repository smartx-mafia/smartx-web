## 版本2 变更速查（v1 已对接过的同学只看这一节）

| # | 变更 | 前端要做的事 |
| --- | --- | --- |
| 1 | **邀请码改为一人一码、永久有效、可被无限次使用** | 从 `GET /user/info` 的 `inviteCode` 取本人邀请码；不再有「剩几个码」的概念 |
| 2 | `GET /user/my_invites`（邀请码列表）**已删除** | 删掉列表页/列表请求，改为展示单个 `inviteCode` |
| 3 | `POST /waitlist_public/reserve_invite`、`POST /waitlist_public/renew_reserve` **已删除** | 删掉「预留邀请码」和「续期心跳」全部逻辑与定时器 |
| 4 | **sessionToken / `x-session-token` 请求头整体取消** | 删掉 sessionToken 的存取与所有相关 header 拼装 |
| 5 | **邀请码改从 `POST /quiz/login` 的 body 传入，且为可选** | `login` 时把落地页拿到的码放进 body；**没有码也照常注册**（自动挂到官方总号名下） |
| 6 | 新增 `inviteNum`（已成功邀请人数） | `/user/info`、`/user/my_result` 可直接展示 |
| 7 | `inviteGenerated` 字段**已删除** | 删掉所有引用；邀请码在注册成功那一刻就已存在，与答题无关 |
| 8 | `POST /waitlist_public/issue_invite_codes`（总号批量发码）**已删除** | 运营接口，前端无影响 |
| 9 | 邀请码状态枚举收敛为 `0 可用` / `3 无效` | 原 `1 预留中` / `2 已核销` 不会再出现（数字保留不复用，旧的数字判断不会误判） |

**一句话概括流程变化**：v1 是「先抢码 → 拿 sessionToken → 答题（心跳续期）→ 验证码 → 注册」；v2 是「（可选）看一眼码 → 答题 → 验证码 → 注册（body 带可选的码）」。

## 1. 通用约定

### 1.1 统一响应结构

所有接口 HTTP 状态码**恒为 200**，业务状态通过响应体的 `code` 字段区分：

```json
{ "code": 200, "message": "SUCCESS", "data": {} }
```

| code | 含义 | `data` 取值 | 前端处理建议 |
| --- | --- | --- | --- |
| 200 | 成功 | 业务数据，或 `true`（无返回值的写接口） | 正常渲染 |
| 401 | 未授权：token 缺失/过期/无效/类型不符 | `false` | 清 token，引导重新登录（见 3.6） |
| 500 | 系统错误：代码异常、数据库错误 | `false` | 提示「服务异常，请稍后重试」，不要展示 `message`（恒为 `ERROR`） |
| 701 | 业务警告：参数错误、状态冲突、验证码错误等 | `false` | **`message` 即可直接展示的英文文案**，中文含义见第 7 节 |

> 判断成功请一律用 `code === 200`，不要用 HTTP 状态码。

### 1.2 认证方式（单一 token）

v2 只剩一种凭证，值格式为 `jwt <token>`（**注意前缀是小写 `jwt`，不是 `Bearer`**）：

| token | 请求头 | 获取时机 | 有效期 | 可访问 |
| --- | --- | --- | --- | --- |
| userToken | `Authorization: jwt <token>` | `POST /quiz/login` 成功后返回（注册或登录都返回） | 15 天 | `/user/*` |

- `/waitlist_public/*` 与 `/quiz/*` 整组**不需要任何 token**。
- `/user/*` 仅接受 `Authorization` 里的 userToken；缺失或失效统一返回 `{ "code": 401, "message": "Authorization error", "data": false }`。
- **v1 的 sessionToken 与 `x-session-token` 请求头已删除**：邀请码不再需要会话载体，直接放进 `/quiz/login` 的 body。

### 1.3 数据格式

- **时间戳**：一律 Unix **毫秒**（如 `joinedAt: 1787581439426`）；无值为 `null`
- **空值**：字符串空值为 `""`，对象空值为 `null`，不会出现 `undefined`
- **布尔标志位**：形如 `telegramCompleted` / `shareCompleted` 的字段是 **number 类型的 `1`/`0`**，不是 boolean；`unlocked` / `submitted` / `locked` / `exists` / `isNewUser` 才是真 boolean
- **分页**：`pageIndex` 从 1 开始；`pageSize` 默认 10、上限 50；返回 `{ list, total, totalPages }`，空列表为 `[]`
- **邮箱**：入参自动转小写；邮箱格式校验为 `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`
- **邀请码**：8 位小写字母数字 `/^[a-z0-9]{8}$/`，入参自动转小写（前端可放心传大写）

### 1.4 防刷与请求锁

- 标注「**lock 2s**」的接口：同一主体（登录用户 / 邀请码）2 秒内只允许一次请求，被锁返回 701 `service is busy`。前端做好按钮防连点即可。
- 邮箱类公开接口有按邮箱的 12 小时窗口限流（详见各接口），超限返回 701 `Too many requests. Try again later.`。
- 全局 IP 限流 600 次/小时，超限返回 701 `request too many times`。

## 2. 枚举与固定文案

### 2.1 邀请码视图状态（数字枚举）

`check_invite` 的 `status`，**前端不要做字符串比较**：

| 值 | 含义 | 对应提示文案（PRD 附录 A.2 原文，可直接展示） |
| --- | --- | --- |
| 0 | 可用 | （空串 `""`） |
| 3 | 无效 / 不存在 | `Invite code not recognized. Check the code and try again.` |

> v2 邀请码**永久有效、无使用次数上限**：一个码可以被任意多人用来注册，被用过之后 `status` 依然是 `0`。原 `1 被预留中` / `2 已核销` 两态已删除，数字不复用，旧代码里的 `status === 1/2` 分支永远不会命中。

### 2.2 三维判型（有序数组，按返回顺序渲染）

结果类接口的 `dimensions` 恒为 3 个元素的有序数组，**顺序即展示顺序，前端勿自行排序**：

| id | key | 中文名 | 英文名 | 两端取值（`side`） |
| --- | --- | --- | --- | --- |
| 0 | risk | 风险姿态 | Risk posture | `degen`（梭哈 / Degen）/ `sniper`（狙击 / Sniper） |
| 1 | decision | 决策依据 | Decision basis | `data`（数据 / Data）/ `gut`（直觉 / Gut） |
| 2 | mode | 交易模式 | Trading mode | `pack`（群体 / Pack）/ `lone`（独行 / Lone） |

每个元素结构：

```json
{ "id": 0, "key": "risk", "nameZh": "风险姿态", "nameEn": "Risk posture",
  "side": "degen", "sideNameZh": "梭哈", "sideNameEn": "Degen" }
```

> 隐藏人格 Risk Monk（`RSK`）的三维在库中为 NULL，此时 `side` / `sideNameZh` / `sideNameEn` 均为 `""`，前端需做空串兜底。

### 2.3 三项属性（有序数组，value 区间 5–99）

`attributes` 恒为 3 个元素的有序数组，顺序固定：

| id | key | 中文名 | 英文名 |
| --- | --- | --- | --- |
| 0 | conviction | 信仰 | Conviction |
| 1 | instinct | 嗅觉 | Instinct |
| 2 | resilience | 复原力 | Resilience |

每个元素结构：`{ "id": 0, "key": "conviction", "nameZh": "信仰", "nameEn": "Conviction", "value": 45 }`

### 2.4 人格 ID

| personaId | 中文名 | 英文名 |
| --- | --- | --- |
| LQD | 送钱者 | The Liquidity Donor |
| AIM | 梭哈仙人 | The All-In Mystic |
| SIG | 喊单军师 | The Signal General |
| CND | K线教主 | The Candle Prophet |
| DIP | 抄底带头大哥 | The Dip Ringleader |
| DOC | 行情老中医 | The Market Doctor |
| CHN | 链上侦探 | The Onchain Detective |
| LMT | 潜伏狙击手 | The Limit Sniper |
| RSK | 风控大师（隐藏款） | The Risk Monk |

> - **v2 起邀请码数量与人格无关**：每人恒定一个码，不限邀请人数（v1 的「普通 5 个 / 风控大师 10 个」已废弃）。
> - 人格解释 `descriptionZh/En`、`roastZh/En`、`colorTag` 当前种子为**空串**，运营补录后自动生效，前端务必做空串兜底。

### 2.5 结果卡片（card）结构

`inviter_card`、`/waitlist_public/result` 的 `card`、`/user/my_result` 解锁态共用同一套卡片字段（**不含邮箱、userId、邀请码等任何身份信息**）：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| resultId | string | 结果 ID（拼分享链接 `/waitlist/?result={resultId}`） |
| personaId | string | 人格 ID（见 2.4） |
| nameZh / nameEn | string | 人格中 / 英文名 |
| imageUrl | string | 人格卡片图链接（按 personaId 匹配配置；未配置为 `""`） |
| descriptionZh / descriptionEn | string | 人格解释中 / 英文（未补录时为 `""`） |
| roastZh / roastEn | string | roast 文案中 / 英文（未补录时为 `""`） |
| colorTag | string | 结果图颜色标记（未补录时为 `""`） |
| dimensions | array | 三维判型有序数组（见 2.2） |
| attributes | array | 三属性有序数组（见 2.3） |
| bestMatch | object | 搭档：`{ personaId, nameZh, nameEn, imageUrl }` |
| naturalRival | object | 天敌：`{ personaId, nameZh, nameEn, imageUrl }` |
| configVersion | string | 结果生成时的配置版本（如 `"v1"`）；历史结果始终按生成时配置展示 |

## 3. 前端接入流程（按用户旅程）

> 本节讲清每一步调哪个接口、带什么、失败怎么处理。字段级定义见第 4–6 节，错误文案见第 7 节。

### 3.0 凭证与本地状态

只有一种凭证，推荐封装：

```js
const authValue = (token) => `jwt ${token}`;

const userHeaders = () => {
  const t = localStorage.getItem('userToken');
  return t ? { Authorization: authValue(t) } : {};
};
```

需要前端本地持有的三样东西：

| 本地状态 | 来源 | 生命周期 |
| --- | --- | --- |
| `inviteCode` | 落地页 URL 的 `?invite=` 参数 | 存起来一路带到 `/quiz/login`；用完可清 |
| 六题答案 | 用户本地作答 | 建议 state + localStorage 双写，刷新可恢复；**后端在 `submit_quiz` 之前不保存任何中间答案** |
| `userToken` | `/quiz/login` 返回 | 15 天；`/user/*` 全程携带 |

> v2 没有任何倒计时、锁、心跳——答题过程中邀请码不会失效，用户答多久都行。

### 3.1 落地页（无凭证）

用户从分享链接进入，URL 形如 `/waitlist/?invite={code}`（可能还带 `&result={resultId}`）：

```text
GET /waitlist_public/inviter_card?inviteCode=xxx     渲染「朋友的人格卡片」
GET /waitlist_public/check_invite?inviteCode=xxx     校验码是否有效
GET /waitlist_public/result?resultId=xxx             （URL 带 result 时）展示公开结果页
```

- `inviter_card`：`data` 为空对象 `{}` 时不展示卡片区（码不存在 / 官方总号码 / 邀请人未提交答题 / 邀请人已隐藏结果）。查看卡片不消耗任何东西。
- `check_invite`：`status === 0` 正常放行；`status === 3` 展示返回的 `message` 并引导用户检查码。
- **`status === 3` 不必阻断流程**：v2 无邀请码也能注册（见 3.4），可以提示「邀请码无效，将以普通方式加入」后继续。
- 用户直接访问落地页（URL 无 `invite` 参数）是完全合法的路径，跳过本节即可。

**把 URL 里的 `invite` 码存进 localStorage**，一路带到 3.4。

### 3.2 答题：本地作答（无凭证）

```text
GET /quiz/questions
```

- 返回 6 题，**题目顺序固定**：`R1`/`R2`（risk）、`D1`/`D2`（decision）、`S1`/`S2`（mode）；选项 ID 形如 `R1_A`。
- **选项顺序不保证**：后端有 `shuffleOptions` 开关，当前测试期为「不打乱」，上线前可能改为乱序。前端一律按返回顺序渲染，**不要按 optionId 排序、也不要依赖 A/B/C/D 的位置含义**。
- 答案存本地，**不逐题上送**；答完直接进 3.3。

### 3.3 邮箱验证码（无凭证）

```text
GET  /waitlist_public/check_email_registered?email=     （建议）
POST /quiz/send_email_code   body: { email }
GET  /waitlist_public/check_email_code?email=           （可选）
```

- `check_email_registered`：发码前预检。`registered=true` 走「欢迎回来」登录文案，`false` 走注册文案——**两种情况都继续发码**，`/quiz/login` 会自动分支。
- `check_email_code`：用户离开页面再回来时，判断验证码是否仍有效（`valid` + `expireSeconds` 做倒计时），避免无谓重发。

限制（701 文案可直接展示）：验证码 6 位数字、**5 分钟有效**；**60 秒重发冷却**；**每邮箱 12 小时最多 5 封**；新码发出后旧码立即失效；单个验证码最多试错 5 次，超限该码作废需重发。

### 3.4 注册 / 登录合一：`POST /quiz/login` → 换取 userToken

```js
// 无需任何 token；inviteCode 可选
// 注意：body 里验证码的字段名就叫 code，与响应体外层的 code 同名但无关
const resp = await post('/quiz/login', {
  email,
  code: verifyCode,                                     // 用户填的 6 位验证码
  inviteCode: localStorage.getItem('inviteCode') || undefined,   // 没有就不传
});

if (resp.code !== 200) return showToast(resp.message);
const data = resp.data;

localStorage.setItem('userToken', data.token);   // 15 天

if (data.isNewUser) {
  // 注册成功 → 立刻提交本地答案（3.5）
} else {
  // 老用户回访：
  //   data.resultId 非空 → 已提交过答题，直接跳结果页
  //   data.resultId 为 "" → 已注册但未提交答题，跳答题引导
}
```

关键行为：

- **不带 `inviteCode` 一样能注册**（v2 取消 invite-only 准入），邀请人自动记为官方总号。
- **邀请码不会被抢占、不会用完**：同一个码可被任意多人使用，不存在「已被使用 / 被其他会话占用」的失败分支。
- 唯一的邀请码失败分支是 701 `Invite code not recognized...`（码不存在或格式不对），**且不消耗验证码**——可以提示用户改码，或直接去掉 `inviteCode` 用同一个验证码重试。
- 已注册邮箱走登录分支，此时**即使带了别人的邀请码也会被忽略**，不会重复绑定关系、不会给任何人发奖励。
- **老用户回访可完全跳过 3.1–3.2**：直接 `send_email_code` → `login` 拿 userToken 和 resultId。

### 3.5 登录后：全部走 `Authorization`

```text
POST /user/submit_quiz          body: { answers }     统一提交六题 → 算分 → resultId
GET  /user/quiz_status                                是否已提交（submitted + resultId）
GET  /user/info                                       bootstrap：身份 + 流程状态 + inviteCode + inviteNum
GET  /user/community_info                             Telegram / X 链接 + 完成状态
POST /user/community_complete   body: { channel }     两渠道分别点击完成（'telegram' | 'x'）
GET  /user/my_result                                  两渠道都完成后返回完整结果 + 真实排名
GET  /user/rank                                       实时排名
POST /user/share_complete                             首次分享标记（首次发放排名提升）
GET  /user/invite_friends                             我邀请的好友（分页）
```

`submit_quiz` 入参必须覆盖全部六题（详见 6.1）：

```json
{ "answers": { "R1": "R1_A", "R2": "R2_D", "D1": "D1_B", "D2": "D2_A", "S1": "S1_C", "S2": "S2_B" } }
```

重复提交幂等：不重算，直接返回已有结果。

**我的邀请码**：注册成功那一刻后端就已为该用户生成唯一邀请码，从 `GET /user/info` 的 `inviteCode` 读取（**与是否答题无关，注册后立即可用**），拼成 `/waitlist/?invite={inviteCode}` 无限次分享。已成功邀请人数看同一接口的 `inviteNum`。

**结果解锁门槛**：必须 `community_complete` 两个渠道都完成，`my_result` 才返回完整卡片与排名；否则返回 `locked: true`。

### 3.6 401 处理

| 场景 | 原因 | 前端动作 |
| --- | --- | --- |
| `/user/*` 返回 401 | userToken 过期 / 无效 / 缺失 | 清掉 `userToken`，引导 `send_email_code` → `login` 重新登录（**不需要邀请码**，本地答案不用清） |

### 3.7 全流程时序图

```text
[落地]  inviter_card + check_invite                         （无凭证；URL 无 invite 时整节跳过）
   ↓ 点「开始测试」
[答题]  GET /quiz/questions → 六题本地作答                   （无凭证、无锁、无倒计时）
   ↓ 答完
[邮箱]  check_email_registered → send_email_code
        （check_email_code 用于回访补查倒计时）
   ↓ 填验证码
[准入]  POST /quiz/login   body: { email, code, inviteCode? }   （无凭证）
          带码   → 邀请人 = 该码的归属者
          不带码 → 邀请人 = 官方总号
        成功：存 userToken
   ↓
[用户]  submit_quiz → community_info → community_complete ×2
        → my_result / rank / info / invite_friends           （全部 Authorization: jwt <userToken>）
        info.inviteCode 即本人永久邀请码，可无限次分享

[老用户回访] send_email_code → login → userToken + resultId   （跳过落地与答题，不需要邀请码）

好友走主线完成注册后，邀请人的 rank 自动提升、inviteNum 自动 +1。
```

## 4. 公开接口 /waitlist_public（无认证）

### 4.1 GET /waitlist_public/check_invite — 查询邀请码状态

- 鉴权：无 · 防刷：按邀请码 lock 2s

**入参（query）**

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| inviteCode | string | 是 | 8 位小写字母数字（大写自动转小写）；格式不符直接返回 701 invalid 文案 |

**出参（data）**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| exists | boolean | 该码是否存在（存在即可用） |
| status | number | 视图状态枚举 `0` / `3`（见 2.1，以此为准） |
| message | string | 对应提示文案（可直接展示；可用时为 `""`） |

> v2 已删除 v1 的 `used` 与 `locked` 两个布尔——码永久可复用，被用过之后仍返回 `status: 0`。

**响应示例**

```json
可用:   { "code": 200, "message": "SUCCESS", "data": { "exists": true,  "status": 0, "message": "" } }

格式错: { "code": 701, "message": "Invite code not recognized. Check the code and try again.", "data": false }
```

### 4.2 GET /waitlist_public/inviter_card — 查询邀请人卡片

- 鉴权：无 · 防刷：按邀请码 lock 2s · Redis 缓存 24h（空结果短缓存 60s 防穿透）
- 语义：好友从分享链接进入时，仅凭邀请码展示**邀请人的公开结果卡片**；不消耗邀请码

```json
{ "code": 200, "message": "SUCCESS", "data": {} }
```

### 5.3 POST /quiz/login — 邮箱验证码登录/注册合一入口

- 鉴权：**无需任何 token** · 无请求锁
- 按邮箱注册状态自动分支：

**① 登录分支（邮箱已注册）**
验证码通过即签发 userToken 并返回原 `resultId`——老用户回访凭此查看结果、排名与邀请数据。不需要邀请码、不发奖励；**即使 body 里带了 `inviteCode` 也会被忽略**。

**② 注册分支（邮箱未注册）**
`inviteCode` 为**可选**入参：

- 带码 → 邀请人 = 该码的归属者
- 不带码 / 传空串 → **邀请人 = 官方总号**（v2 取消 invite-only 准入）

验证码通过后**单事务**完成：创建用户 → 绑定邀请关系（闭包表）→ 邀请人排名提升与 `invite_num + 1` → **为新用户生成其唯一邀请码**。**邀请码不消耗**，同一个码可被任意多人使用。

> 注册成功后前端应立即持 userToken 调 `/user/submit_quiz` 提交本地答案；登录用户直接调 `/user/*` 恢复状态。

**入参（body）**

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| email | string | 是 | 邮箱格式，自动转小写 |
| code | string | 是 | 6 位数字验证码（**注意字段名是 `code`，与响应体的 `code` 同名但无关**） |
| inviteCode | string | 否 | 8 位小写字母数字，大写自动转小写。**不传 / 传空串即无邀请码注册**，自动挂到官方总号名下；登录分支忽略此字段 |

**出参（data）**

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| token | string | userToken（15 天有效），后续 `/user/*` 经 `Authorization: jwt <token>` 携带 |
| userId | string | 用户 ID（13 位数字字符串） |
| isNewUser | boolean | `true`=本次为注册；`false`=本次为登录 / 回访 |
| resultId | string | 登录分支返回原结果 ID（未提交过答题为 `""`）；注册分支恒为 `""` |

**响应示例**

```json
注册: { "code": 200, "message": "SUCCESS", "data": { "token": "eyJ...", "userId": "4119920078712", "isNewUser": true,  "resultId": "" } }
登录: { "code": 200, "message": "SUCCESS", "data": { "token": "eyJ...", "userId": "4119920078712", "isNewUser": false, "resultId": "159ce42f3af64ff689af32b7" } }
```

**失败分支（701，按后端检查顺序）**

| message | 中文含义 | 分支 | 是否消耗验证码 |
| --- | --- | --- | --- |
| `parameters missing` | 验证码未填 | 通用 | 否 |
| `Please enter a valid email address.` | 邮箱格式无效 | 通用 | 否 |
| `user not found` | 账号被封禁 | 登录 | 否 |
| `Invite code not recognized. Check the code and try again.` | 传了 `inviteCode` 但该码不存在，或格式非 8 位小写字母数字 | 注册 | **否**（可去掉 inviteCode 用同一验证码重试） |
| `Verification code is incorrect or expired` | 验证码错误 / 已过期 / 试错超 5 次作废 | 通用 | 错误计数 +1 |

> v2 已无「邀请码被抢 / 已核销 / 被其他会话预留」等失败分支。

## 7. 错误文案速查表（中英对照）

`code=701` 时 `message` 为以下英文原文，**可直接展示给用户**；中文含义供前端理解与自定义文案参考：

| message（原文） | 中文含义 | 出现接口 |
| --- | --- | --- |
| `Invite code not recognized. Check the code and try again.` | 邀请码无效 / 格式错误 / 不存在 | check_invite、inviter_card、login（注册分支） |
| `result not found` | 结果 ID 不存在 | /waitlist_public/result |
| `Please enter a valid email address.` | 邮箱格式无效 | 所有邮箱类接口 |
| `Verification code is incorrect or expired` | 验证码错误 / 已过期 / 试错超 5 次作废 | login |
| `Please wait before requesting a new code.` | 60 秒重发冷却中 | send_email_code |
| `Email send limit exceeded. Try again later.` | 超出每邮箱 12 小时 5 封上限 | send_email_code |
| `Failed to send verification code` | 邮件发送失败，可稍后重试（不消耗次数） | send_email_code |
| `Too many requests. Try again later.` | 查询超出每邮箱 12 小时 30 次上限 | check_email_code、check_email_registered |
| `parameters missing` | 必填参数缺失 | login（验证码未填）、/waitlist_public/result、请求锁中间件 |
| `invalid answers` | 六题答案不完整，或选项不属于对应题目 | submit_quiz |
| `invalid channel` | channel 不是 `telegram` / `x` | community_complete |
| `Quiz not submitted yet` | 尚未提交答题（时序校验） | community_complete |
| `user not found` | 用户不存在或被封禁 | info、rank、invite_friends、login（登录分支） |
| `service is busy` | 2 秒请求锁生效，稍后重试 | 所有标注 lock 的接口 |
| `authorization required` | 请求锁找不到认证主体（userToken 异常） | 请求锁中间件 |
| `request too many times` | IP 限流（600 次/小时） | 全局 |

其他状态码：

- `code=401`，`message` 恒为 `Authorization error`（userToken 缺失 / 过期 / 无效 / 类型不符）
- `code=500`，`message` 恒为 `ERROR`（服务端异常，**不要把 message 展示给用户**）
